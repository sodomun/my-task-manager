# my-task-manager スケジュール（ロードマップ）

`docs/requirements.md` の仕様をベースにした、フェーズ単位（中〜大粒度）の大まかな開発スケジュール案。

開始日は未確定のため、暦日ではなく「週」を相対単位として記載する。実際の着手日が決まり次第、各フェーズに日付を割り当てる。

---

## 全体像

```text
Phase 0  環境構築・土台
Phase 1  認証
Phase 2  今日のタスク（コア）
Phase 3  今後のタスク
Phase 4  完了・復元・期限切れ処理
Phase 5  ダッシュボード
Phase 6  AIナビキャラ（基本連携）
Phase 7  AIの性格設定
Phase 8  仕上げ（設定・データページ・UI調整）
Phase 9  QA・リリース準備
```

依存関係の概略：

```text
Phase 0 → Phase 1 → Phase 2 ──┬─→ Phase 5 ─┬─→ Phase 8 → Phase 9
                                Phase 3 ──┤            │
                                Phase 4 ──┘            │
                                Phase 6 → Phase 7 ──────┘
```

（Phase 6・7 は Phase 2〜4 のタスクデータが揃っていれば並行して着手可能）

---

## Phase 0：環境構築・土台（目安 1週）

- リポジトリ構成の確定（フロント/バックエンド分割 or モノレポ）
- React プロジェクト初期化
- Spring Boot プロジェクト初期化
- MySQL ローカル環境構築、DB接続確認
- 開発環境（Lint/Format、環境変数管理）の整備
- CI（ビルド確認程度）の仮設定

**完了の目安**：フロント・バックエンドの疎通確認（Hello World APIが叩ける）

---

## Phase 1：認証（目安 1〜2週）

対応する仕様：[25. 認証](./requirements.md#25-認証)

- ユーザーテーブル設計
- メールアドレス・パスワードでのサインアップ／ログインAPI
- 認証状態の保持（トークン方式など）
- フロント側のログイン／サインアップ画面

**完了の目安**：ログインしないと今日のタスク画面に入れない状態が作れる

---

## Phase 2：今日のタスク（コア機能）（目安 2〜3週）

対応する仕様：[4. 今日のタスク](./requirements.md#4-今日のタスク)、[6〜9章](./requirements.md#6-完了期限)

このPhaseは層ごと（バックエンド全部→フロントエンド全部）に区切らず、**機能単位の垂直スライス**で進める。各ステップでバックエンドAPIとフロントエンドUIを同時並行的に実装し、ステップの終わりには必ず「実際に動くもの」ができる状態にする（フロント側の`features/todo/`という機能単位のディレクトリ構成とも対応させる。[frontend-architecture.md](./frontend-architecture.md#2-ディレクトリ構成目標)を参照）。

### 2-1. タスク基盤（一覧・作成）

- バックエンド：タスクテーブル設計（種類・課題名・時間帯・完了期限・優先度・状態）、一覧取得API、作成API
- フロントエンド：タスクカードUI（一覧表示）、タスク追加フォーム（必須項目バリデーション含む）

**完了の目安**：タスクを追加でき、一覧に表示される

### 2-2. 表示項目・入力バリデーション

- バックエンド：優先度・時間帯・完了期限のバリデーション（今日のタスクでは優先度必須、等）
- フロントエンド：優先度・時間帯・期限の表示、対応する入力UI

**完了の目安**：カードに全項目が表示され、フォームでバリデーションが効く

### 2-3. 更新・削除

- バックエンド：更新API、削除API
- フロントエンド：タスク選択→編集・削除操作のUI

**完了の目安**：タスクを編集・削除できる

### 2-4. 並び替え

- バックエンド：並び順を永続化するAPI（例：`sortOrder`的なフィールドの更新）
- フロントエンド：ドラッグ＆ドロップによる並び替えUI（ライブラリ選定含む）

**完了の目安**：ドラッグ＆ドロップで並び替えた順序が保存され、リロードしても保持される

**Phase2全体の完了の目安**：今日のタスクを追加・編集・並び替えできる

---

## Phase 3：今後のタスク（目安 1〜2週）

対応する仕様：[10〜11章](./requirements.md#10-今後のタスク)

- 今後のタスク一覧・追加フォーム（課題名・種類必須、その他任意）
- チェックボックスでの複数選択
- 「今日のタスクに追加」時の必須項目チェック（時間帯・完了期限・優先度）と警告UI

**完了の目安**：今後のタスクから今日のタスクへ昇格できる（必須項目チェック込み）

---

## Phase 4：完了・復元・期限切れ処理（目安 1〜2週）

対応する仕様：[13〜16章](./requirements.md#13-タスク完了)

- 完了チェックボックスの実装（完了済みタスクへの移動）
- 完了済みタスク一覧ページ
- タスクの復元機能
- 期限切れタスクの自動移動バッチ／ロジック（日付境界での判定、時間帯の未設定化）

**完了の目安**：完了・復元・期限切れ移動が一通り動く

---

## Phase 5：ダッシュボード（目安 1週）

対応する仕様：[17〜18章](./requirements.md#17-今日の達成状況)

- 今日の達成状況表示（リアルタイム更新）
- 各機能への導線（完了済みタスク／今後のタスク／データ／設定）

**完了の目安**：ダッシュボード経由で全ページへ遷移できる

---

## Phase 6：AIナビキャラ（基本連携）（目安 2〜3週）

対応する仕様：[19〜21章、24章](./requirements.md#19-aiナビキャラ)

- Gemini 2.5 Flash API連携の土台（サーバー側でAPI呼び出し）
- 発話タイミングのフック実装（起動時・ページ遷移時・完了時・削除時・無効操作時）
- タスク状況をプロンプトへ渡す仕組み
- 10秒タイムアウト＋デフォルト回答のフォールバック

**完了の目安**：主要な発話タイミングでAIコメントが表示される（タイムアウト時のフォールバック含む）

---

## Phase 7：AIの性格設定（目安 1週）

対応する仕様：[22章](./requirements.md#22-aiの性格設定)

- 性格プロンプトの保存・編集UI
- デフォルト性格プロンプトの用意
- 性格プロンプトをAI呼び出しに反映

**完了の目安**：性格設定を変えるとAIの発話トーンが変わる

---

## Phase 8：仕上げ（目安 1〜2週）

- 設定ページ（ユーザー情報設定・AI性格設定への導線）
- データページ（優先度低め／過去の達成状況の簡易表示）
- 全体UIの調整（レスポンシブ対応、情報量の見直し）

**完了の目安**：仕様書に記載の全機能が画面から一通り触れる

---

## Phase 9：QA・リリース準備（目安 1〜2週）

- 主要シナリオの手動テスト（タスク追加〜完了〜復元〜期限切れ）
- 例外系の確認（必須項目未入力、AIタイムアウトなど）
- 本番デプロイ環境の準備
- リリース

---

## 全体の目安期間

| フェーズ | 期間目安 |
|---|---|
| Phase 0〜1 | 2〜3週 |
| Phase 2〜5 | 5〜8週 |
| Phase 6〜7 | 3〜4週（Phase 2〜4と並行可） |
| Phase 8〜9 | 2〜4週 |
| **合計** | **目安 10〜16週**（並行実施を考慮） |

個人開発・単独作業を前提としたラフな見積もりであり、実働時間・優先順位の変更により大きく前後する。着手後、実際の進捗を見て随時更新する。
