# 13. フロントエンド側スコープメモ（このファイルのみ backend/ の外の作業）

## 目的

`docs/schedule.md` のPhase1完了条件「**ログインしないと今日のタスク画面に入れない状態が作れる**」を満たすための、フロント側の最小スコープを明確にしておく。

## 重要な訂正

元の案の「今日のタスクのページを簡易作成」は、**`docs/requirements.md` §4の本実装（Phase 2）と混同しないこと**。Phase 1で作るのはあくまで認証フローの動作確認用プレースホルダーであり、タスクカードUIやドラッグ＆ドロップ等は一切含まない。

## Phase 1でフロントに作るもの（最小限）

1. `frontend/` ディレクトリの初期化(React、まだ存在しない場合はここで作成)
2. サインアップ画面: メール・パスワード入力 → `POST /api/auth/signup` → 成功したらトークンを保存して遷移
3. ログイン画面: 同様に `POST /api/auth/login`
4. トークンの保存方法を決める（例: `localStorage`。XSS耐性を重視するなら将来的にHttpOnly Cookie方式への切り替えも検討、ただし今回はJWT+Authorizationヘッダ方式で統一する）
5. ログイン状態の復元: アプリ起動時に保存済みトークンで `GET /api/auth/me` を呼び、成功すればログイン状態として扱う（失敗＝トークン無効ならログイン画面へ）
6. ログアウト: サーバー呼び出し不要。保存したトークンを削除してログイン画面に戻すだけでよい（`06_security_core`参照、JWTはステートレスなのでサーバー側の失効処理は今フェーズでは実装しない）
7. 「今日のタスク」プレースホルダー画面: 固定テキスト（例：「今日のタスク（Phase 2で実装予定）」）を表示するだけのルート
8. ルートガード: トークンが無ければプレースホルダー画面に入れず、ログイン画面へリダイレクトする

## Phase 1でフロントに作らないもの

- タスクカードのUI・並び替え・追加フォーム（Phase 2）
- ダッシュボード（Phase 5）
- AIナビキャラ（Phase 6, 7）

## 依存関係

バックエンド側 `01`〜`12` が完了していること（特に`/api/auth/signup`, `/api/auth/login`, `/api/auth/me`がCORS込みで動作すること）
